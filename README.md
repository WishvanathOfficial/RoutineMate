# RoutineMate

RoutineMate is a full-stack habit and routine management application. It helps people plan routines, build consistency, reflect on progress, and stay accountable through goals, insights, social features, and challenges.

The repository contains a React + TypeScript frontend and an Express + TypeScript backend backed by MySQL. The main product modules are implemented; optional integrations and provider-dependent features need their own credentials and setup. See [Current integrations and limitations](#current-integrations-and-limitations) before enabling them.

## Product features

### Daily routine building

- **Authentication and onboarding** — register, sign in with email or Google, manage sessions, and set up an account.
- **Dashboard** — review routine progress, streaks, and daily activity.
- **Routines** — create, edit, pause, archive, and delete routines; record check-ins and inspect routine history.
- **Routine bundles** — group routines into an ordered sequence and record bundle check-ins.
- **Goals** — create goals, track progress, and manage milestones.
- **Focus timer** — run, pause, resume, cancel, and complete focus sessions; review recent sessions and summary totals.
- **Calendar** — review routine activity by month and inspect a selected day.
- **Journal** — record daily mood and reflections, browse entries by date, and edit prior entries.

### Progress and personalization

- **Stats** — review completion and consistency trends, charts, and insights; export reports as CSV or PDF.
- **Achievements** — earn XP, levels, streak milestones, and achievement badges.
- **Insights** — see a weekly summary and suggested actions. Current summaries are generated by deterministic backend logic, not an external AI model.
- **Profile and settings** — update account details, preferences, notifications, language and measurement settings, theme, and account status.
- **Notifications** — receive and manage reminders, streak-risk prompts, and digest notifications.
- **Installable/offline support** — install the web app where supported and queue routine check-ins while offline for later synchronization.

### Social and community

- **Friends and leaderboards** — find and manage friends, view eligible public profiles, and compare activity.
- **Challenges** — discover, create, join, and track group habit challenges, including check-ins and reactions.
- **Feedback and public roadmap** — submit ideas, search and sort suggestions, vote, and view the public roadmap. The roadmap is also available in a scrollable modal from Feedback.

### Subscription and integrations

- **Google Calendar sync** — connect a Google account and export eligible timed routines to the primary calendar.
- **Billing** — view subscription status and access the account's billing actions when a provider is configured.

## Local development

### 1. Install dependencies

From the repository root:

```bash
npm run setup
```

This installs the frontend and backend dependencies.

### 2. Configure environment

Create `.env` files from the examples, then replace example values with your own local configuration:

```bash
cp .env.example .env
cp backend/.env.example backend/.env
```

The frontend uses the root `.env`; the API uses `backend/.env`. Do not commit either file or use development credentials in a deployed environment.

Important settings:

| Variable                                                                                                                      | Location       | Purpose                                                   |
| ----------------------------------------------------------------------------------------------------------------------------- | -------------- | --------------------------------------------------------- |
| `VITE_API_BASE_URL`                                                                                                           | Root `.env`    | Backend URL; local default is `http://localhost:4000`     |
| `VITE_GOOGLE_CLIENT_ID`                                                                                                       | Root `.env`    | Optional Google sign-in client ID                         |
| `VITE_FEATURE_*`                                                                                                              | Root `.env`    | Optional growth-feature switches; see note below          |
| `PORT`                                                                                                                        | `backend/.env` | API port; local default is `4000`                         |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`                                                                     | `backend/.env` | MySQL connection                                          |
| `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`                                                                                     | `backend/.env` | Separate, strong signing secrets                          |
| `CORS_ORIGIN`                                                                                                                 | `backend/.env` | Frontend origin; local default is `http://localhost:5173` |
| `GOOGLE_CLIENT_ID`                                                                                                            | `backend/.env` | Google sign-in verification; separate from Calendar OAuth |
| `GOOGLE_CALENDAR_CLIENT_ID`, `GOOGLE_CALENDAR_CLIENT_SECRET`, `GOOGLE_CALENDAR_REDIRECT_URI`, `CALENDAR_TOKEN_ENCRYPTION_KEY` | `backend/.env` | Google Calendar export integration                        |
| `RESEND_API_KEY`, `EMAIL_FROM`                                                                                                | `backend/.env` | Outbound email configuration                              |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRO_PRICE_ID`                                                           | `backend/.env` | Billing configuration                                     |

The growth-feature switches are declared in `src/config/featureFlags.ts` and are set to `false` in the example environment. Currently, the Challenges page explicitly checks its flag; do not assume every switch gates every route or integration.

For Google Calendar's one-way export behavior, Google Cloud setup, exact callback URL, and migration details, follow [Google Calendar Sync Setup](docs/Google-Calendar-Sync-Setup.md).

### 3. Create a database and apply migrations

Create the database configured by `DB_NAME` in MySQL, then run the migrations:

```bash
mysql -u root -p
```

```sql
CREATE DATABASE routinemate CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Then, from the repository root:

```bash
npm --prefix backend run db:migrate
```

To load demo data into an empty development database:

```bash
npm --prefix backend run db:seed
```

The backend's `dev` and `start` scripts run a bootstrap step that applies pending migrations and seeds the database if it has no users. Review that behavior before using those scripts against a production database.

### 4. Start the application

From the repository root:

```bash
npm run dev
```

This starts the Vite frontend at `http://localhost:5173` and the API at `http://localhost:4000`. The API health check is available at `http://localhost:4000/health`.

Alternatively, start the frontend and backend separately:

```bash
npm run dev:frontend
```

```bash
npm run dev --prefix backend
```

## API overview

The backend mounts its API under `/api`. Domain route groups include:

`/auth`, `/dashboard`, `/routines`, `/goals`, `/stats`, `/achievements`, `/journal`, `/calendar`, `/calendar-sync`, `/focus-sessions`, `/profile`, `/friends`, `/leaderboards`, `/challenges`, `/routine-bundles`, `/notifications`, `/onboarding`, `/insights`, `/feedback`, `/roadmap`, `/billing`, and `/users`.

Most application endpoints require authentication. `/api/roadmap` is public, and the Google Calendar OAuth callback is an external provider callback. The API uses a shared response format and validates many request payloads with Zod.

## Current integrations and limitations

- **Google Calendar:** one-way, user-triggered export of eligible timed routines. It does not import calendar events or run background synchronization. OAuth credentials, Calendar API enablement, the exact registered callback URL, token encryption configuration, and database migrations are required. See the [setup guide](docs/Google-Calendar-Sync-Setup.md).
- **Billing:** subscription status and UI/API endpoints exist, but hosted Stripe Checkout and Customer Portal are not fully integrated. Setting Stripe environment variables alone does not make real purchases or billing management available.
- **Insights:** weekly summaries and suggestions currently use deterministic backend logic; no AI/LLM provider is connected.
- **Feature switches:** growth switches are present, but they are not uniformly enforced across all feature routes. Treat them as incomplete rollout controls.
- **Online indicator:** the header indicator reflects the browser's online/offline status. Offline check-ins can be queued and retried; this indicator does not continuously verify API reachability.
- **External services:** Google OAuth, email delivery, and billing require valid provider configuration. Core local development does not require those services to be configured.
