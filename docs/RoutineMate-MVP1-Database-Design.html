RoutineMate — Database Design & Requirements

A complete relational data model for the RoutineMate backend, derived from a full pass over the MVP-1 clickable wireframe and the existing React/TypeScript frontend (auth, dashboard, routines, calendar, stats, profile). Target stack: Node.js + TypeScript, Express (route → controller → service), Sequelize ORM on MySQL 8.

1 Context & Scope

What every screen in the app actually needs the database to hold.

The frontend currently runs on in-memory mock APIs (*.api.ts per feature) that stand in for real HTTP calls. Each mock's function signatures and returned shapes were treated as the contract the real backend must satisfy — this model is designed to serve every one of them without changing the frontend's expectations. Two simplifications in the mock layer were deliberately not carried into the schema: (1) Routine.completedToday is a derived flag, not a stored column — a real backend needs one row per habit per calendar day (habit_logs) to support the Calendar and Stats pages honestly; (2) streak / longestStreak are cached, not authoritative — they're recomputed from habit_logs on every check-in write, inside the same transaction.

Authentication

Register / login with email + password, JWT access + refresh tokens, logout. Maps to users + refresh_tokens.

Dashboard

Greeting + quote, today's routines, progress ring, best streak, active routine count — all derived reads over routines + habit_logs.

Routines

CRUD on habits, template quick-start, pause/resume, daily check-in toggle. Core tables: routines, habit_logs.

Calendar

Month grid colored by day status (completed / partial / missed). Pure aggregation over habit_logs — no dedicated table.

Stats & Insights

Weekly completion, category breakdown, 30-day trend, time-of-day activity, per-habit consistency — all aggregated, optionally cached.

Profile & Settings

Account edit, theme / notification preferences, danger-zone delete. Maps to users + user_preferences.

4 Relationships & Delete Behavior

Every association's cardinality and onDelete rule, spelled out explicitly rather than left to defaults.

users1 — 1user_preferences Created automatically on registration. ON DELETE CASCADE.
users1 — Nrefresh_tokens One row per active session/device. ON DELETE CASCADE.
users1 — Nroutines A user's habit list. ON DELETE CASCADE (deleting a user removes their habits).
routines1 — Nhabit_logs Daily check-ins for a habit. ON DELETE CASCADE — logs are meaningless without the parent habit.
users1 — Ngoals (Phase 2) ON DELETE CASCADE.
goalsN — Nroutines (Phase 2) via goal_routines join table — a goal can track multiple habits. ON DELETE CASCADE on both FKs.
users1 — Nachievements (Phase 2) Append-only unlock log. ON DELETE CASCADE.
routines1 — Nreminders (Phase 2) Only needed if a habit gains multiple reminders; MVP-1 keeps reminder fields inline on routines.
users1 — Njournal_entries (Phase 2) UNIQUE(user_id, date) — one entry per day. ON DELETE CASCADE.

What gets indexed, why, and the constraints that do real integrity work (not just Sequelize validators).

Integrity constraints

users.emailUNIQUE

refresh_tokens.token_hashUNIQUE
user_preferences.user_idUNIQUE
journal_entries(user_id, date)UNIQUE (Phase 2)

Table-level notes

  • Charset utf8mb4 / collation utf8mb4_0900_ai_ci everywhere (emoji + case-insensitive email).
  • paranoid: true on users and routines only.
  • All writes to habit_logs that also touch routines.current_streak run in one sequelize.transaction().
  • Check-in endpoint uses upsert() against the unique key, not find-then-write.

8 Phase-2 Extensions (schema-ready, not built)

From the feature analysis roadmap — not required for the MVP-1 backend, included in the ERD so the core tables never need reshaping.

goals, goal_routines, achievements, reminders, and journal_entries are deliberately left out of the MVP-1 Sequelize models/migrations build. They're drawn in the ER diagram above with their full column list so a future migration only has to add tables, never alter the shape of users or routines to accommodate them.
